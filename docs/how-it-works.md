# How it works

`project-sol` is the public front door for `sana.ai.dev`. It is a hub, not a dumping ground.

## The problem

Interesting work is easy to scatter across repos, skills, notes and private folders. Publishing it raw either leaks private context or produces a README full of claims nobody can check.

## The approach

Every candidate goes through the same loop:

1. **Scout** the real workspace or external repo; record what actually exists.
2. **Verify** in a clean copy; record pass, fail or skipped with evidence.
3. **Redact** private paths, hosts, identities and desktop state.
4. **Document** only verified facts; raw logs stay local in `.buddy/`.
5. **Gate** public changes: Sana decides visibility, secrets findings and which projects become flagships.
6. **Wrap** external code with attribution; never vendor it in blind.

The agent does the routine 90%: scouting, checks, docs, branches and release prep. Sana keeps the 10% that changes what the world can see.

## What I learned

A hub is most useful when it says no. The first local batch produced three honest exclusions/write-up candidates rather than three rushed public repos. The form is: claim, evidence, limitation — in that order.
